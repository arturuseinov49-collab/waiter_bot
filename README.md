# Waiter bot — обучение команды заведения

Telegram-бот для официантов, пиццайоло и поваров. Python 3.12, aiogram 3, SQLite.

## Что умеет

- Тесты по разделам меню, количество вопросов задаёт администратор.
- Пауза и продолжение теста после перезапуска программы.
- Разбор каждого ответа и отдельная тренировка по личным ошибкам.
- Защита от повторных нажатий, старых кнопок и одновременных ответов.
- Результаты и роли сохраняются в SQLite; тренировки отделены от статистики тестов.
- Личные результаты, отчёт руководителю, выгрузка Excel.
- Перечитывание вопросов администратором без перезапуска. Ошибочный файл не заменяет уже загруженную базу.

Команды: /start, /test, /resume, /practice, /results, /admin. Бот работает в личном чате.

## Работа в PyCharm

Откройте папку waiter_bot. Интерпретатор проекта — venv/Scripts/python.exe.
В списке запусков доступны **Check project** (вопросы и все тесты без Telegram)
и **Waiter bot** (рабочий бот). Проверки сохраняют отчёт в data/check-results.json.
Можно также открыть check_project.py и выбрать Run в контекстном меню редактора.
Рабочий бот запускайте только после остановки другого экземпляра с тем же токеном.

## Локальный запуск

Создайте окружение Python 3.12 и установите зависимости из requirements.txt.
Скопируйте .env.example в .env, задайте BOT_TOKEN и ADMIN_ID (числовой Telegram ID владельца).
Не запускайте второй экземпляр с тем же токеном, пока работает серверный бот.

```powershell
.\venv\Scripts\python.exe manage.py check
.\venv\Scripts\python.exe -m unittest discover -s tests -v
.\venv\Scripts\python.exe bot.py
```

Пути считаются от папки проекта, независимо от текущей папки терминала.
BOT_DB_PATH по умолчанию data/bot.sqlite3. Секреты, результаты и резервные копии исключены из Git.

## Вопросы

Файлы questions_waiter.xlsx, questions_pizzaiolo.xlsx, questions_cook.xlsx.
Первый лист, первая строка — заголовки:
Категория, Вопрос, Вариант 1, Вариант 2, Вариант 3, Вариант 4, Номер правильного (1-4).
Необязательный столбец «Объяснение» даёт пояснение после ответа.

Проверяются обязательные поля, четыре разных ответа, правильный номер, отсутствие формул и длина текста.
Полные дубликаты не повторяются в тесте. Это проверка структуры, а не фактической правильности рецептов.
При изменении вопроса или ключа старый вариант перестаёт попадать в тренировку.
Уже начатый тест продолжает использовать сохранённую версию вопросов.

## Данные и перенос старой версии

При первом старте роли из user_roles.json, настройки из settings.json и результаты из results.xlsx
однократно импортируются в SQLite. Исходные файлы не удаляются и не меняются.
Неизвестный формат или повреждённая строка останавливают импорт целиком с понятной ошибкой.
Повторный старт не дублирует результаты. Изменять старые JSON/XLSX после миграции бессмысленно —
рабочие данные теперь в SQLite.

Последний ответ сохраняет результат до показа итогов. Повторное открытие итогов не создаёт дубль.
Закрытие незаконченного теста требует подтверждения в боте. История других тестов сохраняется.

## Обслуживание

```text
python manage.py check
python manage.py migrate
python manage.py backup
python manage.py export
```

Backup создаёт согласованный снимок SQLite даже при работающем боте.
Копии содержат результаты сотрудников: храните их приватно. Для отдельного носителя копируйте
снимки из backups/, не живые файлы SQLite/WAL. Копии автоматически не удаляются.

В deploy/ есть шаблоны systemd для автозапуска и ежедневной резервной копии.
Перед установкой сверить путь /root/waiter_bot с реальным расположением и использовать
существующую службу бота, чтобы не запустить два экземпляра.

## Обновление сервера

1. Сохранить текущие исходники, .env, JSON/XLSX и согласованный снимок SQLite (если она уже используется).
2. Проверить python manage.py check и тесты на новой версии.
3. Остановить существующую службу, сохранить окончательную копию данных.
4. Обновить исходники bot.py, manage.py, waiterbot/, requirements.txt; не заменять .env и данные.
5. Выполнить python manage.py migrate, запустить существующую службу.
6. Проверить статус службы и сценарий /start → тест → пауза → продолжить → повторить ошибки.
7. При сбое остановить новую службу и вернуть прежние исходники. Сохранить новую SQLite-базу отдельно:
   ответы, полученные после обновления, старая версия не прочитает автоматически.

Тесты полностью локальные, реальные сообщения сотрудникам не отправляются.
